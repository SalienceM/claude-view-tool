# 在聊天中调用 Workspace Kits

普通聊天和 LOOP 人工接管聊天可以调用当前 Session 已保存的 Kit，不需要先打开 Kit 面板。

可以直接说：

> 看一下当前 Session 有哪些 Kit，先不要执行。

> 按顺序执行“检查环境”“构建”“验证”，前一个成功后才执行下一个，失败就停止。

> 查一下刚才那条 Kit 链的进度。

> 停止刚才那条 Kit 链。

模型先通过 awu_kits 的 list 获取真实 Kit ID，再用 run 提交有序 calls。模型仍须具备工具调用能力，不能只凭文字回复视为执行成功。run 返回运行 ID；status 返回执行器保存的实际状态、退出码、判言结果状态和有长度上限的步骤日志。完整记录仍在 Kit 面板。

## Backend 接入

- OpenAI-compatible / Anthropic API：注入结构化 awu_kits 工具及宿主回调，即使 Session 没绑定任何 Skill 也可使用。实际供应商/模型必须支持工具调用。
- 执行节点上的 Codex、Qwen、Claude 等 CLI：每轮模型输入提供 POST /api/chat-kits 的本机 HTTP 调用说明，使用 CLI 已有的终端或 HTTP 能力。无需注册额外 MCP 或安装 Skill。恢复既有线程时也重新注入，不依赖只在首次创建线程读取的系统约束。
- 老版 codex_connection_mode=ssh 不注入本机入口：SSH 远端的 localhost 不是当前 AgentWithU 执行节点。通过 Relay 连接执行节点并在该节点运行的普通/node 模式不受此限制。
- 自动 LOOP 的内部规划/执行/评审不在此次接入范围；人工接管使用普通聊天流程。

## 顺序、状态与边界

- 单个调用复用原 Kit，保留它的最终判言与产物处理。
- 多个调用保存为一条标题为“Chat 顺序执行”的组合 Kit，通过现有 kit_call 展开机制提交一条冻结计划，不是并发启动多个 kitRun。按顺序执行，首个失败后停止。
- 多 Kit 的输入沿用已有组合机制，在启动时解析；本次不增加“前一个 Kit 新产物动态传给后一个”的数据依赖编排。
- 当前 Session 之外的 Kit 不可调用，名称冲突时应让用户明确选择，不猜 ID。
- 当前聊天轮次中，相同 requestId 和相同计划重试返回原运行回执；同一标识用于不同计划会拒绝。它不是跨重启的永久幂等键。后续轮次先查询状态，不要重复提交已启动任务。
- 已在运行的子 Kit 会阻止聊天重复启动含该子 Kit 的计划。
- queued/running 不代表成功。waiting_approval 需要在面板独立确认；waiting_client 需要在线客户端并打开 Kit 面板。发布确认不能由聊天工具代批。
- 关闭聊天或停止模型回答不会自动取消已经提交的 Kit。可以明确要求取消，也可以用 Kit 面板停止。
- 需要 secret 类型输入（包括嵌套子 Kit）的计划须从面板执行，不能将密码交给模型或写入组合定义。模型不能通过此工具创建任意命令、修改 Kit 或选择其他 Session/节点。

## 权限与生命周期

CLI HTTP 入口只接受 loopback POST 和当前聊天轮次的随机令牌；令牌绑定 Session，轮次完成、失败或取消后撤销。HTTP 调用恢复发起聊天时的身份上下文，绝不因为来源是 localhost 就升级成节点管理员。现有节点权限和高风险能力的独立确认继续生效。

本次功能位于 Backend；更新实际执行节点的 Backend 并重启后，已有聊天在下一轮输入时获得工具。前端沿用已有 Kit 面板及工具消息展示。未进行真实模型计费调用或生产 Kit 执行验收。
