# Skill 安装与运行准备

导入标准 Skill 时保留完整目录，但不执行其中的命令。导入后自动打开“运行准备”；已安装技能卡片也有“运行准备 / 状态”入口。多技能包可逐个选择检查。

## 节点与状态

- 选择的是实际安装依赖的执行节点，而不是浏览器所在设备。RPC 严格按所选节点路由，节点不可用时失败，不回退到默认节点。
- Skill 必须先在该节点的技能库中存在。此功能不会擅自复制技能、凭据或环境到别的机器。
- 运行准备属于节点级管理操作，只有本机身份或该 Relay 节点的主用户可以操作。
- 状态区分：文件已安装/待准备、环境或资源缺失、待配置、需人工处理、正在准备、失败、运行检查通过。
- 安装任务在后端执行；关闭面板或切换 Session 不会取消。重新打开可查看尾部日志。后端重启后，上次未完成任务会标为中断，需重新确认计划后重试。
- “运行检查通过”是声明范围内的检查结果，不是生成 PPT 等业务成果的质量验收。

## 自动准备范围

Python：识别技能根目录 requirements.txt，递归处理目录内的 -r/--requirement 引用。检测循环和越界路径。要求 Python 3.10+；在数据目录 skill-runtime/<技能>/<资源指纹>/venv 内创建独立环境，不安装到系统 Python 或 AgentWithU 环境。pip 使用非交互、隔离配置，仅安装预构建 wheel，不执行源码包 setup/build。无兼容 wheel 时明确失败，不自动降级执行第三方构建。随后执行 pip check 和声明的模块导入检查。

Node：识别 package.json 与 package-lock.json（lockfileVersion 2/3）。复制完整技能到隔离运行目录后，执行 npm ci --ignore-scripts --no-audit --no-fund，再检查依赖树。不会执行生命周期或构建脚本。缺锁文件、Git/本地路径依赖、链接或不安全配置需要先处理；需要脚本的包仍显示人工项，不能仅因依赖下载完成就算就绪。

所有安装都先展示目标节点、依赖、环境路径、检查步骤和人工项，再由用户勾选确认。一次性审批有效期 15 分钟，绑定该节点内的完整技能文件指纹与计划。文件或计划改变后必须重新检查确认。日志有限截断并脱敏，不把日志当作指令。

仅有自然语言安装说明时不会猜测执行。系统软件（字体、LibreOffice、Pandoc 等）、提权操作、付费调用和任意第三方安装脚本不自动执行。

## 可选声明 awu-runtime.json

第三方技能不必修改；标准 requirements/package 文件会自动识别。技能作者可以在根目录提供更明确的运行声明：

    {
      "version": 1,
      "requiredFiles": ["scripts/export.py", "templates/deck.pptx"],
      "requiredCommands": ["pandoc"],
      "requiredEnv": ["IMAGE_API_KEY"],
      "pythonImports": ["pptx", "PIL"],
      "manualSteps": []
    }

- requiredFiles：技能包内部必需资源，缺失时阻止准备。技能入口中具体的 scripts/workflows/references/assets/templates 引用也检查是否齐全；其他 Markdown 链接缺失列为提示，动态路径无法静态推断。
- requiredCommands：程序名列表，仅检查 PATH 中是否存在，不执行版本探测命令或安装系统工具。
- requiredEnv：只检查变量是否存在，不返回值。原生 CLI Skill 需要执行节点进程的环境变量；技能凭据库只对已有 call.py 调用器实际注入的 Backend Skill 算作可用，不会假装把凭据注入所有 CLI。
- pythonImports：由用户在计划中确认后，在隔离 Python 中导入这些模块。模块导入可能执行依赖代码，不属于纯静态检查。
- manualSteps：仍需处理的步骤说明，不是自动执行的命令。依赖可以先准备，但存在人工项时仍显示“需人工处理”。

## 执行、更新与边界

每次组成 Session 约束时，宿主提供已验证技能的隔离解释器/Node 运行副本路径；不往原始 Skill 文件里追加环境说明，也不改变其完整性校验。Agent 应按该路径调用工具；这不是全局 PATH 重写。既有原生 Agent 线程是否立即采用更新约束取决于对应 Backend 的上下文机制，必要时重新绑定或新开会话。

原生 CLI 中运行脚本使用隔离 Python 的绝对路径；Node 脚本使用隔离目录内的完整副本，确保 CommonJS/ESM 就近解析依赖。产物仍应输出到 Session 工作目录，不能改写安装副本。

环境按技能资源指纹区分。更新技能不会覆盖旧环境；旧就绪状态失效，新版本重新准备。旧环境暂时保留，不在更新、卸载时自动递归删除，避免影响仍在执行的会话。

此版本不自动下载未随包提供的模型权重、字体或模板，不自动解决依赖版本冲突，不绕过技能完整性检查，不承诺任意第三方技能零配置运行。
